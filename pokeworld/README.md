# PokeWorld (웹 알파)

설치 없이 **URL로 접속해 바로 플레이**하는 크리처 수집 오픈월드 게임입니다.
PC 브라우저, Android 폰·태블릿, iPhone·iPad가 같은 서버와 같은 월드를 공유합니다.

- 언어/엔진: TypeScript · Vite · Babylon.js(WebGL2 기본, WebGPU 선택)
- 멀티플레이: Node.js + WebSocket(`ws`) · 저장: SQLite(서버, Node 내장 `node:sqlite`), IndexedDB(싱글 플레이)
- PWA: manifest, service worker, 전체 화면·가로 모드, 홈 화면 추가

Minecraft/Cobblemon 프로젝트는 [`reference/fabric-mod`](reference/fabric-mod)에 **참고용(REFERENCE ADAPTER)** 으로만 남아 있고, 웹 게임은 그 바이너리에 의존하지 않습니다.

## 실행

```bash
npm install
npm run dev          # http://localhost:5173  (Vite 클라이언트 + :2567 게임 서버)
```

- **새 게임 / 이어하기** — 싱글 플레이. 서버 없이 브라우저 안의 `LocalGameServer`가 같은 게임 로직을 실행하고 IndexedDB에 저장합니다.
- **온라인 플레이** — 게임 서버가 켜져 있으면 활성화됩니다. 같은 서버의 플레이어끼리 같은 월드를 공유합니다.
- 같은 와이파이의 휴대폰에서는 `http://<PC IP>:5173` 으로 접속하세요.

### 프로덕션 빌드 · 배포

```bash
npm run build        # 타입 검사 + dist/client(정적 파일) + dist/server/main.js
npm start            # :2567 에서 클라이언트·WebSocket(/ws)·/api/health 를 함께 제공
```

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `2567` | HTTP/WebSocket 포트 |
| `POKEWORLD_DB` | `data/pokeworld.sqlite` | 서버 저장 파일 |
| `POKEWORLD_CONTENT` | `content/` | 콘텐츠 팩 폴더 |
| `POKEWORLD_STATIC` | `dist/client` | 정적 클라이언트 폴더 |

두 가지 배포 방식이 모두 가능합니다.

1. **Node 서버 하나**: `npm start` 앞에 HTTPS 리버스 프록시(Caddy, nginx 등)를 두면 `https://game.example.com` 에서 정적 파일과 `wss://game.example.com/ws` 를 함께 제공합니다. WebSocket 업그레이드 헤더를 전달하도록 설정하세요.
2. **정적 호스팅 + 게임 서버 분리**: `dist/client` 를 정적 호스팅에 올리고, 빌드할 때 `VITE_SERVER_URL=wss://server.example.com/ws` 를 주거나 접속 URL에 `?server=wss://…/ws` 를 붙입니다. 서버 없이 올리면 싱글 플레이만 동작합니다.

PostgreSQL로 옮길 때는 `server/src/persistence/PlayerStore.ts` 인터페이스를 구현해 `SqliteStore` 대신 넣으면 됩니다.

## 조작

| PC | 모바일·태블릿 |
| --- | --- |
| WASD 이동, Shift 달리기, Space 점프(비행 시 상승), C 하강 | 왼쪽 화면: 나타나는 가상 조이스틱(끝까지 밀면 달리기) |
| 마우스 카메라(클릭 시 포인터 고정), 휠 줌 | 오른쪽 화면 드래그: 카메라, 두 손가락: 줌 |
| E 대화·조사, F 배틀, R 포획구 던지기, T 탑승 | A · 배틀 · 포획 · 점프 · 탑승 버튼(이동·카메라와 동시에 사용 가능) |
| P 파티, B 가방, M 지도, Q 메뉴 | 상단 파티 · 가방 · 지도 · 메뉴 버튼 |

모바일은 가로 화면이 기본이며, 세로로 들면 회전 안내가 나옵니다. 게임 중 스크롤·확대·더블탭 줌은 막혀 있습니다(`touch-action: none`, 제스처 이벤트 차단).

## 구조

```
client/src/   engine/ (Game, 카메라, 플레이어, 입력, 이펙트) terrain/ (그리디 메셔, 아틀라스, 워커)
              world/ (청크 스트리밍, 구조물) pokemon/ battle/ mount/ air/ (하늘·날씨) quest/ ui/ mobile/ network/ save/
server/src/   sim/Simulation.ts (권위 있는 게임 로직, 브라우저·Node 공용) battle/ spawn/ pokemon/ quest/ legendary/
              world/ player/ persistence/ (SQLite, 콘텐츠 로더) networking/ (WebSocket)
shared/       types/ protocol/ data/ (ContentDB, 스탯) math/ config/ world/ (결정적 지형 생성)
content/      species/ models/ animations/ moves/ spawns/ regions/ ruins/ quests/ legendary/ items/ trainers/ types/
```

**싱글과 멀티가 같은 코드 경로**를 씁니다. 클라이언트는 `GameConnection`(LocalConnection / WsConnection)으로 같은 프로토콜 메시지만 주고받고, 포획 성공, 데미지, 스폰, 보상, 퀘스트 완료, 인벤토리 결과는 모두 `Simulation`이 결정합니다. 이동은 클라이언트가 예측하고 서버가 속도·지형으로 검증해 보정합니다.

### 콘텐츠 팩

크리처 이름, 능력치, 기술, 모델(박스 파츠 템플릿), 애니메이션 값, 스폰 조건(지역·바이옴·시간·날씨·고도·수심·희귀도·퀘스트·구조물·진행도), 지역 배치, 퀘스트, 전설 이벤트 그래프는 모두 `content/` 의 JSON입니다. 엔진 코드에는 크리처 이름이 없습니다. 파일을 바꾸고 다시 빌드하면 다른 콘텐츠 팩으로 교체됩니다. 로드할 때 참조 오류(없는 기술·종·타입 등)를 검사해 목록으로 보여 줍니다.

동봉된 팩은 이 프로젝트를 위해 새로 만든 **오리지널 플레이스홀더**(31종)이며, 기존 게임의 이름·지도·에셋을 복사하지 않았습니다.

## 알파에서 동작하는 것

브라우저에서 실제로 플레이해 확인한 항목입니다(아래 "테스트" 참고).

- 시작 화면 → 새 게임/이어하기/온라인 → 3D 필드
- 초기 지역 「푸른해안 지방」: 새싹마을(회복 센터·상점·연구소·민가), 초원, 숲, 숲 외곽, 강(다리), 호수, 해변, 바다·심해, 섬, 서쪽 언덕의 메아리 동굴(별도 지하 구역), 새벽의 유적
- 플레이스홀더 크리처 31종: 대기·걷기·달리기·수영·비행·배틀 대기·공격·기절 애니메이션, 따라다니는 파트너
- 데이터 기반 스폰, 접근, 턴제 배틀(타입 상성, 자속 보정, 급소, 능력 변화, 흡수·회복, 교체, 아이템, 도망), 경험치·레벨업·기술 습득·진화
- 포획: 배틀 중 포획 + 필드에서 바로 던지기(뒤에서 던지면 보너스), 파티(최대 6) → 보관함
- 연구소 스타터 선택, 상점 구매, 회복 센터, 트레이너 배틀 2명, 퀘스트 7개(진행 HUD), 동굴 출입, 탑승(달리기·수영·비행), 지도, 낮밤·날씨(비·안개)
- 전설 이벤트 그래프 「새벽의 날개」: 소문 → 유적 → 석판 → 동굴 수정 → 밤에 제단 → 수호자 배틀 → 전설 조우. 단위 테스트로 검증했고, 이벤트당 보상은 한 번만 받을 수 있습니다.
- 저장: 싱글 IndexedDB(자동 저장 30초, 탭 숨김·닫기 시 저장), 서버 SQLite. 버전이 있는 세이브와 마이그레이션.
- 멀티플레이: 다른 플레이어 표시(이름표·파트너·탑승), 관심 영역 동기화, 끊기면 지수 백오프로 재연결하고 토큰으로 같은 캐릭터 복귀
- PWA: 설치, 서비스 워커, 오프라인 앱 셸(싱글 플레이)

### 성능 구조

64m×64m 청크를 플레이어 주변 3×3 / 5×5 / 7×7만 로드하고 멀어지면 해제합니다(경계에서 왕복하지 않도록 히스테리시스 적용). 그 밖에 다음을 적용했습니다.

- 메싱 Web Worker
- 그리디 메싱
- 텍스처 아틀라스: 머티리얼 플러그인이 병합된 면에서도 블록 단위로 타일링
- 거리별 LOD: 1 / 2 / 4 m 샘플링
- 나무·풀·수정 thin instance
- 크리처 파츠 인스턴싱과 오브젝트 풀
- 구조물 메시 병합
- 프러스텀 컬링, 크리처 거리 컬링, 안개
- 서버 측 거리별 AI 갱신 주기 감소(타임 휠)
- 청크 공간 인덱스, 스폰 예산(플레이어당·전역), 파티클 예산
- 그림자 품질 4단계, 렌더 해상도 조절, 프레임 제한

품질 프리셋 기본값은 다음과 같습니다.

| | 렌더 해상도 | 시야 | 그림자 | 기타 |
| --- | --- | --- | --- | --- |
| 모바일(저사양) | 0.75 | 3×3 | 꺼짐 | 풀 꺼짐, 파티클 150 |
| PC(고사양) | 1.0 | 7×7 | 중간 | — |

## 테스트

```bash
npm run typecheck
```

| 묶음 | 확인 내용 |
| --- | --- |
| `play` | 시작 → 이동 → 카메라 → 스타터 → 스폰 → 접근 → 배틀 → 포획 → 파티 → 지도 → 저장·불러오기 |

| `features` | 상점, 회복, 트레이너, 동굴 출입, 탑승·비행 |
| `net` | 2인 접속, 순간이동 차단, 서버 강제 종료(SIGKILL) → 재연결 → 같은 플레이어·저장 유지 |

## 아직 없는 것 (다음 단계)

- 탈것 제작(보트·잠수정·글라이더·비행기), 제작·채광 시스템, 광석·지하 층
- 해저 잠수, 하늘 고도층·하늘섬
- 체육관, 더블 배틀, 레이드
- 배틀 기믹(메가·Z·다이맥스·테라스탈) 인터페이스와 콘텐츠
- 상태 이상, 계정 로그인

성능은 실제 GPU로 측정하지 못했습니다. 이 개발 환경의 브라우저는 소프트웨어 렌더링이라 1280×720에서 8~10 FPS가 나옵니다. 30~60 FPS 목표는 실제 기기에서 확인이 필요합니다(설정 → FPS 표시). 같은 환경에서 측정한 PC 고사양 프리셋의 프레임당 드로우 콜은 약 230~330회입니다.
