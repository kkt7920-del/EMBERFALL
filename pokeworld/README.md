# PokeWorld (웹 알파)

설치 없이 **URL로 접속해 바로 플레이**하는 포켓몬 수집 오픈월드 게임입니다. 월드는 1×1×1 블록으로 이루어져 있습니다.
PC 브라우저, Android 폰·태블릿, iPhone·iPad가 같은 서버와 같은 월드를 공유합니다.

- 언어/엔진: TypeScript · Vite · Babylon.js(WebGL2 기본, WebGPU 선택)
- 멀티플레이: Node.js + WebSocket(`ws`) · 저장: SQLite(서버, Node 내장 `node:sqlite`), IndexedDB(싱글 플레이)
- PWA: manifest, service worker, 전체 화면·가로 모드, 홈 화면 추가

Minecraft/Cobblemon 프로젝트는 [`reference/fabric-mod`](reference/fabric-mod)에 **참고용(REFERENCE ADAPTER)** 으로만 남아 있고, 웹 게임은 그 바이너리에 의존하지 않습니다.

## 실행

```bash
npm install
npm run dev          # http://localhost:5173  (Vite 클라이언트 + :2567 게임 서버)
```

- **새 게임 / 이어하기** — 싱글 플레이. 서버 없이 브라우저 안의 `LocalGameServer`가 같은 게임 로직을 실행하고 IndexedDB에 저장합니다.
- **온라인 플레이** — 게임 서버가 켜져 있으면 활성화됩니다. 같은 서버의 플레이어끼리 같은 월드를 공유합니다.
- 같은 와이파이의 휴대폰에서는 `http://<PC IP>:5173` 으로 접속하세요.

### 프로덕션 빌드 · 배포

```bash
npm run build        # 타입 검사 + dist/client(정적 파일) + dist/server/main.js
npm start            # :2567 에서 클라이언트·WebSocket(/ws)·/api/health 를 함께 제공
```

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `2567` | HTTP/WebSocket 포트 |
| `POKEWORLD_DB` | `data/pokeworld.sqlite` | 서버 저장 파일 |
| `POKEWORLD_CONTENT` | `content/` | 콘텐츠 팩 폴더 |
| `POKEWORLD_STATIC` | `dist/client` | 정적 클라이언트 폴더 |

두 가지 배포 방식이 모두 가능합니다.

1. **Node 서버 하나**: `npm start` 앞에 HTTPS 리버스 프록시(Caddy, nginx 등)를 두면 `https://game.example.com` 에서 정적 파일과 `wss://game.example.com/ws` 를 함께 제공합니다. WebSocket 업그레이드 헤더를 전달하도록 설정하세요.
2. **정적 호스팅 + 게임 서버 분리**: `dist/client` 를 정적 호스팅에 올리고, 빌드할 때 `VITE_SERVER_URL=wss://server.example.com/ws` 를 주거나 접속 URL에 `?server=wss://…/ws` 를 붙입니다. 서버 없이 올리면 싱글 플레이만 동작합니다.

서버 없이 싱글 플레이만 올릴 때는 `npm run build:embed` 를 쓰면 `dist/artifact` 에 경로가 상대적인 빌드가 만들어집니다(서비스 워커와 설치 버튼 없음). 아무 정적 호스팅의 하위 경로에 올려도 동작합니다.

PostgreSQL로 옮길 때는 `server/src/persistence/PlayerStore.ts` 인터페이스를 구현해 `SqliteStore` 대신 넣으면 됩니다.

## 조작

| PC | 모바일·태블릿 |
| --- | --- |
| WASD 이동, Shift 달리기, Space 점프(비행 시 상승), C 하강 | 왼쪽 화면: 나타나는 가상 조이스틱(끝까지 밀면 달리기) |
| 마우스 카메라(클릭 시 포인터 고정), 휠 줌 | 오른쪽 화면 드래그: 카메라·조준, 두 손가락: 줌 |
| **R** 볼 손에 들기/넣기, **1–9** 볼 고르기, **휠** 볼 바꾸기(볼을 든 동안), **G** 볼 휠 | **BALL**: 탭 = 손에 들기, 누르고 있기 = 조준·힘 모으기, 떼기 = 던지기 |
| **왼쪽 클릭**: 짧게 = 바로 던지기, 누르고 있기 = 힘 모으기, 떼기 = 던지기 | 오른쪽 아래 볼 칩 탭 = 볼 휠, 조준 중에도 조이스틱으로 이동 |
| E 대화·조사·포켓몬 정보, F 배틀, T 탑승, X 도감 | 포켓몬 길게 누르기 = 정보, A · 배틀 · 점프 · 탑승 버튼 |
| P 파티, B 가방, M 지도, Q 메뉴 | 상단 파티 · 가방 · 지도 · 메뉴 버튼 |

모바일은 가로 화면이 기본이며, 세로로 들면 회전 안내가 나옵니다. 게임 중 스크롤·확대·더블탭 줌은 막혀 있습니다(`touch-action: none`, 제스처 이벤트 차단).

## 구조

```
client/src/   engine/ (Game, 카메라, 플레이어, 입력, 효과음) terrain/ (복셀 그리디 메셔, 아틀라스, 워커, 셰이더)
              world/ (청크 스트리밍·LOD) pokemon/ (PokemonAssetRegistry, Bedrock·glTF 로더, Molang, PokemonView)
              capture/ (볼 투척·궤적·포획 연출) battle/ mount/ air/ (하늘·날씨) ui/ mobile/ network/ save/
server/src/   sim/Simulation.ts (권위 있는 게임 로직, 브라우저·Node 공용) battle/ spawn/ pokemon/ quest/ legendary/
              world/ player/ persistence/ (SQLite, 콘텐츠 로더) networking/ (WebSocket)
shared/       types/ protocol/ data/ (ContentDB, 스탯) math/ config/ world/ (결정적 복셀 지형 생성, 물리)
              capture/ (CaptureCalculator, 볼 물리) pokemon/ (PokemonSpeciesRegistry)
content/      pokemon/{species,models,textures,animations,cries}/ capture/ (balls.json, capture.json) moves/ spawns/
              regions/ ruins/ quests/ legendary/ items/ trainers/ types/
```

**싱글과 멀티가 같은 코드 경로**를 씁니다. 클라이언트는 `GameConnection`(LocalConnection / WsConnection)으로 같은 프로토콜 메시지만 주고받고, 포획 성공, 데미지, 스폰, 보상, 퀘스트 완료, 인벤토리 결과는 모두 `Simulation`이 결정합니다. 이동은 클라이언트가 예측하고 서버가 속도·지형으로 검증해 보정합니다.

### 콘텐츠 팩

포켓몬 종(도감 번호·이름·타입·능력치·히트박스·이동 방식·애니메이션 이름), 기술, 타입 상성, 볼 계수, 포획 계수, 스폰 조건(지역·바이옴·세부 바이옴·시간·날씨·고도·수심·희귀도·레벨), 지역 배치, 퀘스트, 전설 이벤트 그래프는 모두 `content/`의 JSON입니다. 로드할 때 참조 오류(없는 기술·종·타입 등)를 검사해 목록으로 보여 줍니다.

- 종 데이터: 101종(1세대 중심, 일부 이후 세대), 기술 91개, 18타입 상성표
- **3D 모델은 동봉하지 않습니다.** 모델이 없는 종은 다른 동물이나 임의의 크리처로 바꾸지 않습니다. 대신 히트박스 크기의 체크 상자에 `MISSING_POKEMON_ASSET #025 Pikachu`를 표시합니다. 사용할 권리가 있는 모델(Bedrock `.geo.json`+`.png`+`.animation.json` 또는 `.glb`)은 게임 메뉴의 **포켓몬 3D 모델**에서 연결하거나 `content/pokemon/assets.json`에 넣으면 됩니다. 방법은 [`content/pokemon/README.md`](content/pokemon/README.md)를 보세요.
- 포획 공식의 모든 계수(볼 배율과 조건, 상태 이상, 저레벨·고레벨 보정, 알파·전설·희귀도, 크리티컬 단계)는 `content/capture/*.json`에 있습니다.

## 알파에서 동작하는 것

브라우저에서 실제로 플레이해 확인한 항목입니다(아래 "테스트" 참고).

- 시작 화면 → 새 게임/이어하기/온라인 → 블록 월드
- **블록 월드**: 1×1×1 블록 60종, 32×32 청크, 텍스처 아틀라스(풀 윗면·옆면·아랫면, 통나무 윗면·옆면, 잎; nearest 필터). 노이즈 층(대륙·침식·산·세부·강)과 3D 노이즈로 절벽, 오버행, 협곡을 만듭니다. 동굴은 작은 동굴, 대동굴, 지하 강, 수정 동굴, 광산, 깊은 동굴, 고대 유적이며 입구가 지상과 이어집니다.
- 초기 지역 「푸른해안 지방」: 새싹마을(연구소·회복 센터·상점·민가·가로등·분수), 길, 초원, 숲 외곽 → 숲 → 깊은 숲, 강(산 → 폭포 → 계곡 → 초원 → 바다로 이어지는 단차 강, 다리), 호수, 해변, 바다(해안 → 얕은 바다 → 먼바다 → 깊은 바다 → 심해; 모래·자갈·해초·산호·바위·해저 협곡·난파선·가라앉은 유적), 언덕, 눈 덮인 산, 화산, 메아리 동굴, 새벽의 유적. 지역 전체가 한 월드로 이어져 있고 먼 곳은 LOD로 보입니다.
- 하루: 낮 · 오후 · 노을 · 밤 · 새벽. 해가 움직이고 하늘, 주변광, 안개, 그림자 방향이 바뀝니다. 밤에도 달빛으로 포켓몬을 알아볼 수 있습니다.
- 스폰: 지역·바이옴·세부 바이옴·시간·날씨·고도·수심·희귀도 조건, 플레이어당 예산, 크기 기반 예산, 알파 개체(더 크고 강함). 먼 포켓몬은 AI 갱신 주기가 낮습니다.
- **볼 포획**: 오른쪽 아래 「Poké Ball ×12」 표시. 볼 9종(몬스터볼, 슈퍼볼, 하이퍼볼, 퀵볼, 다이브볼, 다크볼, 넷트볼, 타이머볼, 리피트볼)을 키, 휠, 볼 휠로 고릅니다. 조준점은 범위 안의 포켓몬 위에서 노란색이 되고 「Pikachu / Lv. 8」을 보여 줍니다.
  - 볼은 서버가 시뮬레이션하는 실제 투사체입니다(중력, 공기 저항, 회전, 바운드, 굴러감).
  - 빗나간 볼은 바닥에 멈추고, 다가가면 주워서 가방으로 돌아옵니다.
  - 맞으면 다음 순서로 연출합니다: 충돌음 → 볼이 열림 → 빛 → 입자 → 에너지 → 빨려 들어감·작아짐·사라짐 → 닫힘 → 떨어짐 → 흔들림 최대 3번 → 성공(별·「Gotcha!」) 또는 탈출(파열·빛, 화난 반응).
  - 크리티컬 포획은 특별한 섬광과 강한 흔들림 1번으로 연출합니다. 잡은 포켓몬은 파티에 6마리가 차 있지 않으면 파티로, 차 있으면 PC 보관함으로 갑니다. 도감은 발견에서 포획으로 바뀝니다.
- 배틀 「포획」 → 볼 휠 → 조준 → 실제 투척 → 연출 → 결과. 배틀이 먼저 필요한 포켓몬(EncounterRule)이 있습니다. 상태 이상(잠듦, 얼음, 마비, 독, 화상), 성격, 특성, 성별, 개체 크기.
- 포켓몬 정보: E 또는 길게 누르기로 이름, Lv, 타입, HP, 성별, 상태를 봅니다. 상세 화면에서는 능력치, 기술, 특성, 성격, 잡은 볼, 만난 곳을 봅니다. 도감(X)과 PC 보관함도 있습니다.
- 연구소 스타터(이상해씨·파이리·꼬부기), 상점, 회복 센터, 트레이너 배틀, 퀘스트, 탑승(달리기·수영·비행), 지도, 날씨
- 전설 이벤트 그래프 「새벽의 날개」: 소문 → 유적 → 석판 → 동굴 수정 → 밤에 제단 → 수호자 배틀 → 전설 조우(단위 테스트로 검증)
- 저장: 싱글 IndexedDB(자동 저장), 서버 SQLite. 버전이 있는 세이브와 마이그레이션(v1 세이브의 옛 크리처는 포켓몬으로 바뀝니다).
- 멀티플레이: 다른 플레이어 표시, 관심 영역 동기화, 재연결 후 같은 캐릭터로 복귀
- PWA: 설치, 서비스 워커, 오프라인 앱 셸(싱글 플레이)

### 성능 구조

- 32×32 청크를 플레이어 주변 5×5(모바일·중간) / 7×7(고사양)만 블록으로 그리고, 바깥은 128 m LOD 타일로 그립니다. 가까운 사각형이 모두 준비된 뒤에 LOD에 구멍을 내서, 순간이동해도 빈 곳이 보이지 않습니다.
- 멀어진 청크는 해제합니다. 복셀은 LRU 저장소에 두고, 플레이어 주변은 고정합니다.
- 메싱은 Web Worker 최대 3개에서 합니다. 면은 타일·색·AO·빛이 같으면 그리디로 합칩니다. 하늘빛·블록빛 BFS 조명을 씁니다.
- 풀·꽃은 컷아웃 머티리얼 1개로 그리고, 가까운 청크에서만 보입니다.
- 프러스텀 컬링, 안개를 씁니다. 포켓몬 모델은 스킨드 메시 1개(드로 콜 1회)이고, 모델이 없는 표시는 인스턴스로 그립니다.
- 서버 AI는 거리에 따라 갱신 주기를 2 / 4 / 10 / 20틱으로 낮춥니다. 스폰 예산과 파티클 예산(PC 1200 / 모바일 150)이 있습니다.

| 프리셋 | 렌더 해상도 | 블록 시야 | LOD 링 | 그림자 | 풀 | 파티클 |
| --- | --- | --- | --- | --- | --- | --- |
| 낮음(모바일 기본) | 0.75 | 5×5 | 1 | 꺼짐 | 꺼짐 | 150 |
| 중간 | 0.9 | 5×5 | 2 | 낮음 | 1청크 | 400 |
| 높음(PC 기본) | 1.0 | 7×7 | 3 | 중간 | 2청크 | 1200 |

| `features` | 상점, 회복, 트레이너, 동굴(지형에 파인 지하 바이옴), 탑승·비행 |
| `models` | 모델 패널에서 파일 연결 → 표시가 모델로 바뀜, 뼈가 따로 움직임, 제거하면 MISSING 표시로 돌아옴 (`tests/fixtures/test-rig`, 포켓몬이 아닌 테스트용 상자 리그) |
| `net` | 2인 접속, 순간이동 차단, 서버 강제 종료 → 재연결 → 같은 플레이어·저장 유지 |
| `pwa` | manifest, 서비스 워커, 오프라인 셸 |

### 성능 측정에 대해

이 개발 환경의 브라우저는 소프트웨어 렌더링(SwiftShader)입니다. 그래서 화면 FPS(5~8)는 실제 GPU의 성능을 나타내지 않고, **60 FPS(PC) / 30 FPS(모바일) 목표는 실제 기기에서 확인하지 못했습니다**(설정 → FPS 표시로 확인할 수 있습니다). GPU와 무관하게 측정한 값은 다음과 같습니다(`tests/e2e/perf.mjs`, 6초 걷기).

- 프레임당 게임 로직 CPU 시간: 대부분 1~2 ms(p95 1.3~5 ms). 고사양 프리셋의 숲·해안에서 가끔 튀는 값은 소프트웨어 렌더러가 GL 업로드를 막는 데서 생깁니다. CPU 프로파일에서 메인 스레드는 대부분 쉬고 있습니다.
- 드로 콜: 낮음 43~128, 중간 149~246, 높음 96~216
- 정점 수: 낮음 44만~89만, 중간 68만~110만, 높음 130만~250만
- 청크 1개 생성+메싱(워커): 평균 20~90 ms

## 아직 없는 것 (다음 단계)

- **포켓몬 3D 모델 파일**: 동봉하지 않습니다. 연결 기능과 로더(Bedrock·glTF, 뼈별 애니메이션, 절차적 움직임)는 테스트용 리그로 검증했습니다. 실제 포켓몬 모델로는 확인하지 못했습니다.
- 효과음 파일: 이벤트(ball_throw, capture_beam, ball_shake, capture_success 등)와 재생 경로는 있습니다. 소리는 WebAudio로 합성한 임시음이고, `Sfx.register(name, url)`로 파일을 연결할 수 있습니다.
- 블록 설치·파괴, 제작·채광
- 체육관, 더블 배틀, 레이드, 계정 로그인
- 실제 기기에서의 FPS 측정과 그에 따른 튜닝
