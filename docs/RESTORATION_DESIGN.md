# EMBERFALL 복원 설계 v0.1

이 문서는 업로드된 `emberfall-save` JSON에서 **직접 확인된 구조**, 그 구조에서 **합리적으로 추론한 부분**, 원본 소스가 없어 새로 정한 **복원 설계안**을 분리해서 기록한다.

## 1. 세이브에서 직접 확인된 구조

- `passives`

## 2. 구조에서 강하게 추론되는 점

아래는 필드 배열 길이와 반복 패턴을 근거로 한 추론이며 원본 코드가 없어 100% 확정할 수 없다.

- `ranks`, `awake`, `traits`가 모두 5개이므로 한 직업의 핵심 액티브 스킬은 5개 구조였을 가능성이 높다.
- `skillrank0`~`skillrank4` 옵션도 같은 5스킬 체계를 지지한다.
- `traits[i]`가 두 칸이므로 스킬별 2개의 성장/변형 포인트를 저장하려던 구조로 보인다.
- `loadouts`가 2개이므로 장비 프리셋 2세트를 지원한다.
- `collection`의 `slot:appearanceId` 키는 외형 수집/형상변환 컬렉션으로 보인다.
- `uniqueMod`는 일반 `mod`와 별개의 고유/전설급 효과 인덱스로 보이지만 정확한 효과표는 복원할 수 없다.

## 3. 복원 설계 원칙

1. **세이브 호환 우선**: 기존 필드명과 숫자 코드를 유지한다.
2. **원본 미확인 부분은 별도 레이어**: 전투 공식, 스킬 모션, AI를 세이브 스키마와 분리한다.
3. **주무기=속성, 보조무기=행동 변형**의 역할을 명확히 나눈다.
4. **스킬 자체의 개성**은 스킬별 2개 폼으로 만든다. 보조무기 변형은 그 위에 한 번 더 작동한다.
5. `uniqueMod`는 추후 전설/신화 아이템의 특수 규칙으로 확장한다.

## 4. 버서커 5스킬 복원 설계안

아래 이름과 동작은 **새 설계안**이다. 세이브 파일에는 원래 스킬명이 들어 있지 않다.

### Skill 0 — 파쇄
기본: 전방 넓은 도끼 베기.
- 폼 A `처형`: 좁고 강한 2연격, 보스/단일 대상 중심.
- 폼 B `지진`: 피해는 낮아지지만 부채꼴 충격파가 남음.

### Skill 1 — 투척
기본: 전투도끼 투사체.
- 폼 A `사냥꾼`: 빠르고 직선적인 단일 투척.
- 폼 B `분쇄륜`: 느리지만 큰 회전 도끼가 다단히트.

### Skill 2 — 붕괴 도약
기본: 지정 지점으로 도약 후 내려찍기.
- 폼 A `분화구`: 착지 중심 대형 원형 피해.
- 폼 B `파열선`: 착지 후 전방으로 균열이 진행.

### Skill 3 — 혈쇄
기본: 피의 사슬/도끼줄로 적을 붙잡는 기술.
- 폼 A `인력`: 적을 사용자 쪽으로 당김.
- 폼 B `절단`: 당기지 않고 사슬 경로를 따라 지속 피해.

### Skill 4 — 광폭
기본: 짧은 시간 공격성과 범위를 크게 높이는 폭발형 기술.
- 폼 A `광란`: 이동/공격 속도 중심.
- 폼 B `혈폭`: 즉시 주변 폭발 + 짧은 공격 강화.

## 5. 속성 레이어

주무기의 `el`은 모든 스킬의 **피해 성질/후속 상태**를 바꾼다. 스킬의 기하 구조 자체는 바꾸지 않는 것을 원칙으로 한다.

- 노말: 순수 물리, 가장 높은 기본 피해.
- 불: 화상/지속 피해.
- 번개: 짧은 연쇄 또는 감전 중첩.
- 얼음: 둔화/빙결 축적.
- 바람: 밀치기/이동성/범위 보정.
- 어둠: 출혈/흡수/저주 계열.
- 빛: 표식/폭발/보호 계열.

정확한 수치는 원본에서 복원할 수 없으므로 밸런스 단계에서 결정한다.

## 6. 보조무기 변형 레이어

보조무기 `mod`는 스킬의 **공간적 행동**을 바꾼다.

- 분산: 하나의 공격을 여러 갈래로 분할.
- 확장: 범위/크기 증가.
- 관통: 충돌 후 계속 진행.
- 낙하: 공격을 목표 지점 상공/지면 낙하형으로 변환.
- 연쇄: 적중 대상에서 다음 대상으로 전이.
- 회귀: 공격이 되돌아오며 재적중 가능.
- 공전: 일부 공격체가 사용자 주변을 일정 시간 회전.

모든 스킬에 똑같이 적용하지 않고, 각 스킬별로 `지원 / 변환 / 금지` 호환표를 둔다. 이것이 동일 루틴 반복을 줄이는 핵심이다.

## 7. 스킬 × 변형 호환 설계

| 스킬 | 분산 | 확장 | 관통 | 낙하 | 연쇄 | 회귀 | 공전 |
|---|---|---|---|---|---|---|---|
| 파쇄 | 지원 | 강지원 | 제한 | 변환 | 지원 | 금지 | 변환 |
| 투척 | 강지원 | 지원 | 강지원 | 지원 | 강지원 | 강지원 | 지원 |
| 붕괴 도약 | 금지 | 강지원 | 변환 | 강지원 | 지원 | 금지 | 변환 |
| 혈쇄 | 지원 | 지원 | 변환 | 금지 | 강지원 | 강지원 | 강지원 |
| 광폭 | 금지 | 지원 | 금지 | 변환 | 지원 | 금지 | 강지원 |

`강지원`은 자연스럽고 강한 시너지, `변환`은 원래 기술의 형태를 크게 바꾸는 특수 구현, `제한`은 효과 일부만 적용, `금지`는 해당 조합을 아이템 생성/장착 단계에서 막는 방식이다.

## 8. `uniqueMod` 재설계

세이브에는 0~6 범위의 `uniqueMod`가 반복되지만 원래 효과는 알 수 없다. 따라서 숫자 자체는 보존하되 효과 테이블은 새로 둔다.

권장 역할:
- 일반 `mod`: 위치/형태/궤적 변환
- `uniqueMod`: 스킬 규칙을 깨는 전설 효과

예: 처치 시 재시전, 체력 소모로 강화, 각성 상태에서 2회 사용, 마지막 타격만 폭발 등.

## 9. 구현 단계

### Phase 1 — 저장/인벤토리 복구
- JSON import/export
- 구버전 필드 보존
- 아이템 목록/장착/프리셋
- 속성/변형/등급 표시

### Phase 2 — 스킬 체험장
- 5개 스킬
- 스킬별 A/B 폼
- 주무기 속성 적용
- 보조무기 변형 호환표 적용
- 더미/피해 로그

### Phase 3 — 전투 코어
- 이동, 충돌, 몬스터 AI
- 드롭, 경험치, 골드
- `field`, `chaosGate` 드롭 테이블

### Phase 4 — 성장
- ranks/awake/traits
- paragon/aether
- 두 개 loadout
- 외형 collection

## 10. 호환 정책

복원판의 저장 형식도 최상단에 다음 값을 유지한다.

```json
{
  "format": "emberfall-save",
  "version": 1,
  "savedAt": 0,
  "state": {}
}
```

알 수 없는 필드는 삭제하지 않고 그대로 통과시키는(pass-through) 방식으로 저장한다. 이렇게 해야 나중에 원본 파일을 찾았을 때 역호환/병합 가능성이 높다.
